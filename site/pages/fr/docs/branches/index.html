Au quotidien

Branches et travail en parallèle.

Plusieurs sessions peuvent travailler sur le même projet en même temps sans se marcher dessus. Vous choisissez une branche ; Code lui donne son propre dossier, appelé worktree, et rien n'atteint votre copie de travail principale tant que vous ne l'avez pas fusionnée.

Comment ça marche

Un worktree est un second dossier du même dépôt Git, extrait sur une autre branche. Code les crée pour vous, à côté de votre projet : un projet situé dans Projects/game a ses worktrees dans Projects/game.worktrees/<branch>. Quand vous choisissez une branche pour une session :

  • la branche déjà extraite utilise le dossier du projet lui-même ;
  • une branche qui a déjà un worktree le réutilise ;
  • toute autre branche, nouvelle ou existante, reçoit un nouveau worktree.

La règle qui garantit la sécurité : un seul rédacteur par dossier. Votre copie de travail vous appartient, ou appartient à la session qui y travaille.

Lancer une session sur une branche

  1. Ouvrez le sélecteur de brancheDans Start Session, après avoir choisi le projet, choisissez la ligne Branch.
  2. Choisissez ou créez une brancheChaque branche indique ce qui va se passer : Repository folder (dossier du dépôt), Isolated workspace ready (espace isolé prêt), ou Code will prepare an isolated workspace (Code va préparer un espace isolé). Pour en créer une, choisissez New branch, nommez-la (par exemple feature/better-jump), choisissez éventuellement son point de départ, puis choisissez Use branch.
  3. LancezCode prépare le worktree et y démarre la session. La liste des sessions la signale par un badge worktree.

Nova fait de même quand elle délègue : demandez-lui de travailler sur plusieurs choses à la fois, et elle peut donner à chacune sa propre branche.

L'onglet Worktrees

Dans l'onglet GitHub de Code, ouvrez un projet et choisissez Worktrees. Chaque ligne affiche la branche, son état, son avance ou son retard sur la branche par défaut, les modifications non commitées, son dernier commit, et les sessions et discussions qui l'utilisent.

ÉtatSignification
In useUne session y travaille.
Uncommitted changesDu travail qui n'a pas encore été commité.
MergedTout ce qui est sur la branche se trouve dans la branche par défaut. Vous pouvez le supprimer sans risque.
IdleRien en cours, rien en attente.
Folder missingLe dossier a été supprimé en dehors de Code. Clean up missing l'oublie et conserve la branche.

Depuis le menu d'une ligne : Open in Code, New session here, Copy path et Remove worktree…. New worktree, en haut, en crée un sans lancer de session.

Branches autorisées, ou main uniquement

Le menu en haut de l'onglet Worktrees définit la règle du projet. Branches allowed permet aux sessions de travailler sur une branche dans son propre worktree. Main only garde toutes les sessions dans la copie de travail : la ligne Branch disparaît de Start Session, et Nova ne délègue pas sur une branche. Utilisez-le pour les projets où un second dossier perturberait vos outils.

Terminer : fusionner et faire le ménage

  1. Commitez dans le worktreeDemandez à la session de commiter son travail, ou faites-le vous-même.
  2. FusionnezOuvrez une pull request, ou fusionnez la branche dans votre branche par défaut en local, depuis une copie de travail propre. Code ne fusionne pas les branches à votre place.
  3. Supprimez le worktreeChoisissez Remove worktree…. Le dossier est supprimé ; la branche et ses commits sont conservés, sauf si vous cochez aussi Also delete the branch, proposé une fois la branche entièrement fusionnée.

Code refuse de supprimer un worktree qui a des modifications non commitées. Il liste aussi les fichiers ignorés qui partiraient avec le dossier, comme les fichiers .env ou les environnements virtuels, pour que vous puissiez les récupérer avant. Si des sessions y tournent encore, le bouton propose de les arrêter d'abord.

Quand découper, et quand s'en abstenir. Les branches brillent pour les tâches indépendantes : un écran de sélection de niveau, la prise en charge des manettes et un meilleur saut. Deux tâches qui touchent les mêmes fichiers gagnent à être faites l'une après l'autre, dans une seule session.
