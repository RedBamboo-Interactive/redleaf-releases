Au quotidien

Sessions de code.

Code est l'endroit où les agents travaillent sur vos projets. Une session est un travailleur IA persistant, attaché à un projet, que vous pouvez observer, orienter et retrouver plus tard. Autour d'elle, Code affiche vos commits, vos issues, vos tests et vos branches, et vous permet de modifier les fichiers vous-même.

Ce qu'il vous faut

  • Git, pour tout ce qui se fait dans Code. Git for Windows, ou le paquet git de votre distribution.
  • La GitHub CLI (gh), connectée avec gh auth login, pour les fonctions GitHub : lister et créer des issues et des pull requests, et les tackles. Les commits, les branches, les tests, les revues et les contrôles de santé n'ont besoin que de Git.
  • La chaîne d'outils de votre projet, pour lancer ses tests.

Les réglages de Code affichent une liste Dependencies avec ce qu'il a trouvé. Choisissez Check again après avoir installé quelque chose.

Ajouter un projet

Ouvrez l'onglet GitHub dans Code et choisissez + (Add repository) en haut de la liste Repos.

  • Existing checkout : un dossier qui est déjà un dépôt Git. Donnez-lui un nom et son chemin, puis choisissez Register. Le dépôt distant est détecté par Git.
  • New project : Code crée le dossier, initialise Git sur main et l'enregistre. Choisissez Create.

Code ne clone pas. Pour travailler sur un projet qui n'existe que sur GitHub, lancez d'abord git clone, puis enregistrez le dossier.

Lancer une session

  1. Nouvelle sessionDans Sessions, choisissez New ou appuyez sur Ctrl+N.
  2. Choisissez le projetFiltrez et sélectionnez-le. Si le projet autorise les branches, une ligne Branch vous permet d'en choisir ou d'en créer une : voir Branches et travail en parallèle.
  3. Choisissez le fournisseur et la qualitéFast, Standard, Deep ou Research. Standard convient à la plupart des travaux ; Deep et Research prennent plus de temps et réfléchissent davantage. Choisissez ensuite Go.
  4. Rédigez le briefLa session démarre vide : votre premier message est le brief. Dites ce que vous voulez, à quoi ressemble « terminé », et comment le vérifier.

Depuis l'en-tête d'un dépôt dans l'onglet GitHub, New Session en lance une immédiatement avec les réglages par défaut.

Travailler avec une session

Une session fonctionne comme une discussion : des carrés d'étapes pour chaque action, des cartes d'autorisation, des suites mises en file, Esc pour interrompre. Quelques points sont propres à Code :

  • Mode plan. Appuyez sur Shift+Tab et la session lit et planifie sans rien modifier. Quand le plan est prêt, choisissez Execute Plan, ou répondez pour le faire réviser.
  • État. Le point de chaque session indique son état : doré quand elle travaille, bleu-vert quand elle est inactive, gris quand elle est arrêtée, rouge en cas d'erreur, ambre quand elle vous attend. L'onglet du navigateur affiche (!) tant qu'une session vous attend. Alt+↑ et Alt+↓ passent d'une session à l'autre.
  • Info. Alt+I affiche le fournisseur, le modèle, la qualité, le coût et les jetons, ainsi que ses Permissions : le seul réglage que vous pouvez changer pendant qu'elle tourne.
  • Reprendre. Envoyez un message à une session arrêtée et elle reprend. Si vous atteignez la limite d'utilisation de votre fournisseur, la session se met en pause ; envoyez un message une fois la limite réinitialisée.
  • Stop, Dismiss, Close. Stop met fin au processus et garde la session dans la liste. Dismiss la masque sans l'arrêter. Close fait les deux. Retrouvez les sessions fermées dans More › Browse archives et rouvrez-les avec Reopen.

Relire ce qui a changé

L'onglet Code est un explorateur et un éditeur de fichiers. Les fichiers modifiés récemment par une session IA portent une petite étincelle, et le panneau Git liste les Recent AI Changes (modifications récentes de l'IA), les modifications non commitées et les commits récents. Ouvrez un fichier modifié et choisissez Diff against HEAD pour voir exactement ce qui a bougé. Enregistrez vos propres modifications avec Ctrl+S.

Depuis ces panneaux, Code ne fait ni commit, ni push, ni fusion à votre place. Demandez à la session de commiter, ou utilisez Git vous-même.

Les tackles travaillent dans le dossier de votre projet. Un tackle change de branche dans la copie de travail principale. N'en lancez pas pendant que vous ou une autre session y travaillez.

Laisser Nova déléguer

Vous n'êtes pas obligé de lancer les sessions vous-même. Demandez le travail à Nova dans une discussion, et elle peut le confier à une session Code sur le bon projet, sur sa propre branche si le projet le permet. La discussion affiche une carte Delegated to Code avec Open in Code, et un cercle rose tant qu'elle tourne. Quand la session se termine, Nova reçoit le résultat, le relit et vous dit ce qui s'est passé. Elle peut renvoyer des retours à la même session jusqu'à ce que ce soit bon.

Vous pouvez ouvrir la session déléguée dans Code à tout moment pour la suivre, approuver une étape ou ajouter un message.

Une session déléguée ne partage ni la mémoire de Nova ni la discussion. Nova écrit dans le brief ce dont la session a besoin, et c'est une raison de plus pour garder les décisions de votre projet dans son espace de travail.
