L'API locale.

Tout ce que font les applis passe par une API locale, et tout ce que font vos agents aussi. Elle se décrit elle-même : un agent peut donc trouver le bon appel sans deviner, et chaque appel porte une identité signée qui dit qui l'a demandé et pour qui.

Deux services

ServiceAdresseCe qu'il fait
RedLeafhttp://127.0.0.1:18804Entités, applis, extensions, discussions, automatisations, paramètres, authentification
RedComputehttp://127.0.0.1:18800Le moteur d'IA : sessions, inférence, parole, images et autres tâches

Les deux n'écoutent que sur votre propre machine. L'accès à distance passe par RedLeaf. Les ports sont indiqués dans Settings › System et dans les paramètres d'AI Compute.

Découverte

Commencez par /discover sur l'un ou l'autre service. C'est une courte carte des domaines, chacun avec ses routes, ses schémas et ses concepts. Cherchez-y, ou ouvrez un domaine :

GET /discover                      la carte
GET /discover/find?q=automations   la recherche
GET /discover/automations          un domaine en entier
GET /openapi.json                  le document OpenAPI

Les extensions ajoutent leurs propres domaines : ce que vous voyez dépend donc de ce qui est installé. C'est tout l'intérêt : un agent lit la découverte pour obtenir le contrat en vigueur, au lieu de se fier à une route dont il se souvient.

Authentification

Chaque appel nécessite un jeton, envoyé sous la forme Authorization: Bearer <token>. La découverte indique "authMode": "Required" ; une route qui ne mentionne aucune authentification propre n'est pas publique pour autant.

  • Les applis dans votre navigateur génèrent, à partir de votre session, des jetons d'exécution de courte durée, pour une appli à la fois.
  • Les agents en reçoivent un dans la variable d'environnement REDLEAF_EXECUTION_TOKEN de leur session.
curl -H "Authorization: Bearer $REDLEAF_EXECUTION_TOKEN" \
  http://127.0.0.1:18804/auth/execution-context

/auth/execution-context indique au nom de qui parle le jeton : l'appli, l'acteur, le bénéficiaire, la discussion d'où il vient, son parent, et quand il expire. Un jeton n'accorde jamais plus que ce qu'a le droit de faire la personne pour qui il agit.

{{icon:shield-check}}

Les jetons restent sur la machine. N'envoyez un jeton d'exécution qu'aux RedLeaf et RedCompute locaux. Ne le mettez jamais dans une URL, un journal ou le stockage d'un navigateur, et ne l'envoyez jamais à un autre site web. Les skills fournies avec Nova respectent ces règles ; respectez-les dans les vôtres.

Chaque appel est consigné

Comme chaque jeton est signé, RedLeaf sait de quelle appli, de quel agent et de quelle discussion vient chaque appel. Dans Compute › Jobs, chaque tâche affiche son origine, son acteur et son bénéficiaire, sa chronologie et son coût, et vous pouvez filtrer selon chacun de ces critères. C'est ainsi que vous répondez à « qui a lancé ceci, et pourquoi ? » pour tout ce qui s'est exécuté.

Écrire vos propres outils

Le plus simple pour automatiser RedLeaf, c'est de le demander à un agent : il détient déjà un jeton signé, lit la découverte, et montre ses appels sous forme de carrés d'étapes que vous pouvez vérifier. Pour tout ce qu'un agent doit faire toujours de la même façon, consignez-le dans une skill.
