Sauvegardes.

La base de données de RedLeaf contient vos discussions, vos agents, leur mémoire et chaque entité. Sauvegardez-la de façon planifiée et, si vous voulez survivre à la perte de l'ordinateur, gardez une copie chiffrée hors site.

Ce qui est couvert

SauvegardeContenu
Sauvegarde de la base de donnéesDiscussions, agents, mémoire et pages de l'espace de travail, skills, automatisations et toutes les autres entités. Avec la portée Everything, toute la base de données.
Copie hors siteLa base de données, plus les clés de chiffrement de RedLeaf, vos ressources (images, audio, vidéo) et les fichiers de l'espace de travail.

Aucune des deux ne couvre vos propres dossiers de projet, vos documents ni quoi que ce soit d'autre sur votre disque. Sauvegardez-les comme vous le faites d'habitude, et poussez souvent votre code vers un dépôt distant.

Sauvegardes de la base de données

Ouvrez Settings › Storage › Database et trouvez Backup.

  • Automatic : Off, Daily ou Weekly (désactivé, quotidien ou hebdomadaire), et l'heure dans Runs at. Les sauvegardes automatiques restent désactivées tant que vous ne les activez pas.
  • Scope : Entities only (entités seulement), ou Everything (tout).
  • Retention : combien de sauvegardes automatiques conserver, de 1 à 10. Les sauvegardes manuelles sont conservées à part, jusqu'au même nombre en plus.
  • Le dossier : laissez-le vide pour utiliser l'emplacement par défaut, %LOCALAPPDATA%\RedLeaf\backups sous Windows.

Back up everything en fait une tout de suite. Export entities enregistre vos entités seules. Last backup vous indique quand la dernière a eu lieu.

Les sauvegardes sont des dumps PostgreSQL standard. Il n'y a pas encore de bouton de restauration pour elles dans la préversion. Si vous devez en restaurer une, demandez de l'aide sur le Discord de Leaf.

Copie hors site

La copie hors site va dans un bucket Cloudflare R2 qui vous appartient. Elle est chiffrée sur votre ordinateur avant de partir : Cloudflare ne stocke jamais que des données chiffrées. Elle n'est disponible que sous Windows pour l'instant, et seul un administrateur peut la configurer.

  1. Créez un bucketDans Cloudflare, créez un bucket R2 et une clé d'accès pour celui-ci.
  2. Connectez-leDans Settings › Storage › Backups, choisissez Set up off-site copy. Saisissez l'Account ID, le bucket, la Data location (choisissez European Union pour garder les données dans l'UE), l'Access key ID et la Secret access key.
  3. Conservez la phrase de récupérationRedLeaf affiche une seule fois une phrase de récupération de huit mots. La copie est bloquée exprès : recopiez-la à la main dans votre gestionnaire de mots de passe, cochez I saved it in my password manager, puis retapez-la pour confirmer. Sans elle, la copie ne peut pas être déchiffrée.
  4. Activez les copies nocturnesBack up every night s'exécute après la sauvegarde locale de la base de données. Back up now en lance une immédiatement.

Durée de conservation des copies

Un nettoyage hebdomadaire supprime les points de restauration de plus de 35 jours et en garde un par semaine pendant 12 semaines. Le bucket est verrouillé : rien de ce qu'il contient ne peut être supprimé ni écrasé pendant 30 jours, même depuis RedLeaf, si bien qu'une erreur ou un agent compromis ne peut pas effacer votre historique.

Testez-la avant d'en avoir besoin

RedLeaf lance automatiquement un test de restauration le premier dimanche de chaque mois. Lancez-en un vous-même avec Run a restore test now. Pour récupérer quelque chose, choisissez Restore to a folder : choisissez ce qu'il faut restaurer, le point de restauration et, si vous le souhaitez, un seul chemin. La restauration se fait toujours dans un nouveau dossier, jamais par-dessus vos données en service.

Pour une récupération complète sur un nouvel ordinateur, RedLeaf écrit dans le bucket un fichier qui explique comment restaurer. L'ordre est le suivant : d'abord les clés, puis l'installation de RedLeaf, puis la base de données, puis les ressources et les fichiers de l'espace de travail.
