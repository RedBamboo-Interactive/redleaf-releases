Niveaux d'accès.

Un niveau d'accès détermine ce qu'un agent peut faire dans une session sans vous demander d'abord. Il en existe quatre, de la simple lecture à l'exécution de n'importe quoi. Vous seul pouvez les modifier, depuis Settings, en personne.

Les quatre niveaux

NiveauCe que l'agent peut faire
PlanIl lit et planifie. Il ne modifie rien tant que vous ne le laissez pas passer à l'action.
AskIl modifie les fichiers du projet et vous demande avant toute autre chose, par exemple avant d'exécuter une commande.
AutoUn contrôle de sécurité autorise les actions courantes et bloque les actions risquées.
FullIl fait n'importe quoi sans demander. Disponible uniquement quand Full access est activé.

Le niveau par défaut est Auto, avec Full access désactivé. Les heartbeats, les planifications et les autres sessions sans surveillance ne peuvent pas attendre qu'une personne autorise une étape : Auto leur permet de continuer à travailler tout en arrêtant ce qui est risqué.

Plan et Auto nécessitent un fournisseur qui les prend en charge. Sinon, la session utilise Ask à la place.

Où le régler

PortéeOù
Tous les agentsSettings › Agent permissions › New sessions. Utilisé par chaque agent qui n'a pas son propre niveau.
Un agentLa page de l'agent, dans son champ Access level. Choisissez un niveau, ou Use default (utiliser le niveau par défaut).
Une sessionLa boîte de dialogue Info de la session, sous Permissions. Le changement s'applique immédiatement.

Une session ne peut pas dépasser le niveau avec lequel elle a démarré, et un agent ne peut jamais relever son propre niveau. Dans Code, Shift+Tab active ou désactive le mode Plan, et revient au niveau précédent quand vous en sortez.

Autorisations

Quand une action a besoin de votre permission, l'agent s'arrête et affiche une carte d'autorisation. Son carré d'étape prend un anneau ambre, et la discussion est marquée comme en attente de votre réponse.

  • Allow once (autoriser une fois) laisse cette seule action s'exécuter.
  • Allow for this session (autoriser pour cette session) cesse de demander pour ce type d'action jusqu'à la fin de la session.
  • Deny (refuser) la refuse, et l'agent continue sans elle.

Les actions refusées par la politique, sans vous demander, apparaissent sous forme de courte note sous la dernière réponse de l'agent.

Full access

Activer Full access dans Settings › Agent permissions ouvre un avertissement que vous devez lire et accepter. En résumé, il dit ceci : avec Full access, un agent exécute n'importe quelle commande sans demander. Il peut supprimer des fichiers, réécrire l'historique git, effacer une base de données ou envoyer vos données ailleurs. Le plus souvent, ce serait une erreur. Parfois, c'est parce que quelque chose qu'il a lu, comme un message Discord, un e-mail ou une page web, le lui a demandé.

Avant de l'activer :

  • gardez une sauvegarde hors de portée de l'agent, et testez une restauration au moins une fois ;
  • poussez votre code souvent ;
  • sachez ce que RedLeaf sauvegarde : sa propre base de données, pas vos autres fichiers ;
  • ne laissez pas de mots de passe ni de clés d'API dans des fichiers en clair ;
  • préférez Ask ou Auto pour tout ce qui lit du contenu non fiable, et utilisez Full pour une seule session à la fois, quand vous en avez besoin.

Le désactiver ramène chaque niveau par défaut Full à Auto, et les sessions Full en cours à leur niveau par défaut. Si le texte de l'avertissement change, Full access se désactive jusqu'à ce que vous acceptiez la nouvelle version.

{{icon:warning}}

Les agents lisent des choses que vous n'avez pas écrites. Les pages web, les e-mails et les messages peuvent contenir des instructions destinées à une IA. Plus le niveau d'accès est bas, moins une telle instruction peut faire de dégâts. C'est la vraie raison de réserver Full access aux moments où vous en avez besoin.
