  • Écris une issue pour le tableau de bord trop lent, avec ce que tu vérifierais en premier.

  • Qu'est-ce qui a été fusionné depuis la 2.4 ? Prépare les notes de version.

Comment ça marche

  1. Enregistrez le dépôtDans l'onglet GitHub de Code, ajoutez le dossier de votre projet. Les issues et les pull requests demandent la GitHub CLI connectée ; les commits, les tests et les revues n'ont besoin que de Git.
  2. Des signalements aux issuesNew Issue rédige une issue complète à partir de votre courte description, avec le contexte et les critères d'acceptation. Ou demandez à Nova de l'écrire à partir de ce que vos utilisateurs ont signalé.
  3. Lancez Auto TackleUne IA travaille sur l'issue : elle crée une branche, implémente le correctif, lance les tests et ouvre une pull request.
  4. Relisez, puis fusionnezSur un commit, Auto Review donne un verdict d'IA avec ses remarques, et Health Check lance toutes les suites de tests, sans IA. Approuvez le tackle, puis fusionnez-le avec Merge, ou écartez-le avec Dismiss.
  5. Gardez les notes de versionDemandez à Nova ce qui est entré depuis la dernière version. Elle lit l'historique et rédige les notes sous forme de page modifiable.
{{icon:shield-check}}

Votre branche principale reste à vous. Chaque tackle travaille sur sa propre branche. Rien n'est fusionné avant que vous choisissiez Merge, et un tackle écarté ne touche jamais au projet.

Ce qu'il vous faut

GitGit pour Windows, ou le paquet git de votre distribution.
La GitHub CLIgh, connectée avec gh auth login, pour les issues, les pull requests et les tackles.
Un fournisseur de codePar exemple Codex ou Anthropic, connecté pendant la configuration.
