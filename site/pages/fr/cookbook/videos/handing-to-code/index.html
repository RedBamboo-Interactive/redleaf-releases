Confier le travail à Code

Un client trouve un bug, et quelqu’un doit le corriger sans casser ce qui fonctionne déjà. Nova confie le travail à une session de code et vous le rapporte, prêt à fusionner. La vidéo est en anglais ; la transcription ci-dessous est en français.

Ce que vous verrez

  • Le rapport de bug d’un client dans une discussion, et Nova qui confie la correction à Code avec un brief : une carte Delegated to Code avec Open in Code, et un cercle rose tant que la session tourne.
  • La branche et le worktree de la session dans l’onglet Worktrees de Code, à côté de votre copie de travail principale, intacte.
  • La session au travail : elle trouve la cause, la corrige avec des tests, lance toutes les suites de tests et ouvre une pull request.
  • Le callback dans la discussion, la relecture de Nova avec Auto Review, et la fusion, qui attend votre autorisation.
  • Ce qui se passe en dessous : le brief, la session dans Code, un seul rédacteur par dossier, les tests dans le worktree, le callback, et un nouveau passage demandé à la même session.

Transcription

Ouverture

Un client trouve un bug dans votre produit. Quelqu’un doit le corriger, sans casser ce qui fonctionne déjà.

Alors je confie le travail à une session de code, et je vous le rapporte, prêt à fusionner.

Le rapport

Tout commence dans une discussion : le rapport de bug d’un client. Code est l’application de RedLeaf pour les projets logiciels, et une session y est un travailleur de code qui reste sur un projet jusqu’à ce que le travail soit fini. Alors j’écris un brief, et je confie la correction à une session. Le cercle rose reste allumé tant qu’elle travaille.

Sa propre branche

La session a sa propre branche, et Code donne à cette branche son propre dossier, appelé worktree. Votre copie de travail principale, le dossier du projet dans lequel vous travaillez, n’est pas touchée, donc vous pouvez continuer à y travailler.

La regarder travailler

Ouvrez la session, et vous pouvez la regarder travailler. Elle trouve la cause, la corrige, avec un test, lance toutes les suites de tests, puis ouvre une pull request : la modification, prête à être relue.

Relecture et fusion

Quand elle a fini, la discussion reçoit un callback, une note qui dit que la session est terminée, et je le prends en main. Je lis la modification, et je lance Auto Review, la relecture par IA propre à Code. La correction est petite, et tous les tests passent. Fusionner, c’est votre décision. Vous approuvez, je fusionne, et la réponse au client est prête, il ne vous reste qu’à l’envoyer.

Sous le capot

Alors, qu’y a-t-il en dessous ? Une discussion, et un brief. La session ne partage pas ma mémoire, alors j’écris ce dont elle a besoin. Elle tourne dans Code, sur le dépôt de votre projet, et vous pouvez l’ouvrir à tout moment pour la regarder, autoriser une étape ou ajouter un message.

Sa branche a un worktree, à côté de votre projet. Un seul rédacteur par dossier, donc votre copie de travail reste la vôtre. Les tests tournent dans le worktree, et le travail revient sous forme de pull request.

Quand la session a fini, le callback me fait revenir. Je relis, avec Auto Review comme second avis, et rien n’atteint votre branche principale avant que vous l’approuviez. S’il faut un autre passage, j’envoie mes remarques à la même session, et elle reprend là où elle s’était arrêtée.

Récapitulatif

Donc : je confie le travail à une session Code, avec un brief. Elle travaille sur sa propre branche, et votre copie de travail reste la vôtre. Et rien n’est fusionné tant que vous ne l’avez pas approuvé.

La prochaine fois : demandez, tout simplement. Tout ce que vous avez vu ici, avec des mots simples. À bientôt.
