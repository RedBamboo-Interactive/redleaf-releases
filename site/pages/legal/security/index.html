Security

Last updated: 13 November 2026

Report a vulnerability

Email becherel.laurent@gmail.com with “RedLeaf security” in the subject. Please don't post it on Discord or in a public GitHub issue first.

Useful to include:

  • the RedLeaf version and platform,
  • what an attacker can do, and what they need first,
  • steps or a proof of concept to reproduce it.

You will get a reply within a few days. We will keep you informed while we fix it, credit you in the release notes if you want, and ask you to wait for a fixed version before you publish details. We will not pursue anyone who reports in good faith, stays within their own installation, and does not access other people's data.

In scope

The RedLeaf launcher and installer, the RedLeaf service and its built-in apps (Nova, Code, Workspace, Compute), plugins published on the official release feed, the release feed itself, and this website. Vulnerabilities in an AI provider or another connected service belong with that service.

How downloads are verified

  • Every component is published with a release record in a signed release feed. The launcher checks the signature and the SHA-256 hash of each download before installing it, and refuses anything that does not match.
  • The download section of this site reads the same feed and shows the installer's SHA-256 so you can check it yourself.
  • On Linux, the install script verifies the launcher against the signed release record before running it.
  • During the preview, the Windows installer is not yet signed with a Windows publisher certificate, so SmartScreen can show “Unknown publisher”. This is expected.

Running agents safely

Agents work at the access level you choose. Plan only reads and plans. Ask edits its own workspace and asks before anything else. Auto decides what is safe and asks about the rest. Full does anything without asking, and is only available once you turn Full access on. Start with Ask, and raise the level per agent once you trust a workflow.
