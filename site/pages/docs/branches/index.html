Everyday use

Branches and parallel work.

Several sessions can work on the same project at once without stepping on each other. You choose a branch; Code gives it its own folder, called a worktree, so nothing reaches your main checkout until you merge it.

How it works

A worktree is a second folder of the same Git repository, checked out on another branch. Code creates them for you, beside your project: a project in Projects/game gets its worktrees in Projects/game.worktrees/<branch>. When you pick a branch for a session:

  • the branch that's already checked out uses the project folder itself;
  • a branch that already has a worktree reuses it;
  • any other branch, new or existing, gets a fresh worktree.

The rule that keeps this safe: one writer per folder. Your checkout belongs to you, or to whichever session is working in it.

Start a session on a branch

  1. Open the branch pickerIn Start Session, after picking the project, choose the Branch row.
  2. Pick or create a branchEach branch says what will happen: Repository folder, Isolated workspace ready, or Code will prepare an isolated workspace. For a new one, choose New branch, name it (for example feature/better-jump), optionally pick what it starts from, and choose Use branch.
  3. GoCode prepares the worktree and starts the session there. The session list marks it with a worktree badge.

Nova does the same when she delegates: ask her to work on several things at once and she can give each one its own branch.

The Worktrees tab

In Code's GitHub tab, open a project and choose Worktrees. Each row shows the branch, its state, how far ahead or behind the default branch it is, uncommitted changes, its last commit, and which sessions and discussions use it.

StateMeaning
In useA session is working there.
Uncommitted changesWork that hasn't been committed yet.
MergedEverything on the branch is in the default branch. Safe to remove.
IdleNothing running, nothing pending.
Folder missingThe folder was deleted outside Code. Clean up missing forgets it and keeps the branch.

From a row's menu: Open in Code, New session here, Copy path and Remove worktree…. New worktree at the top makes one without starting a session.

Branches allowed, or main only

The menu at the top of the Worktrees tab sets the project's policy. Branches allowed lets sessions work on a branch in its own worktree. Main only keeps every session in the checkout: the Branch row disappears from Start Session, and Nova won't delegate onto a branch. Use it for projects where a second folder would confuse your tools.

Finishing: merge and clean up

  1. Commit in the worktreeAsk the session to commit its work, or do it yourself.
  2. Merge itOpen a pull request, or merge the branch into your default branch locally, from a clean checkout. Code doesn't merge branches for you.
  3. Remove the worktreeChoose Remove worktree…. The folder is deleted; the branch and its commits are kept unless you also tick Also delete the branch, which is offered once it's fully merged.

Code won't remove a worktree with uncommitted changes. It also lists ignored files that would go with the folder, such as .env files or virtual environments, so you can rescue them first. If sessions still run there, the button offers to stop them first.

When to split, and when not to. Branches shine for independent jobs: a level select screen, controller support and a better jump. Two jobs that touch the same files are better done one after the other, in one session.
