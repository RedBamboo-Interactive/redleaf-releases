From a bug report to a reviewed pull request.

Your product has users, and users find bugs. Code shows your repository's open issues next to its commits and tests. Hand an issue to Auto Tackle and it comes back as a pull request on its own branch, tested and waiting for you. Nothing reaches your main branch until you merge it.

What you can ask

  • Two customers say CSV exports lose their accents. Find the issue and tackle it.
  • Write an issue for the slow dashboard, with what you'd check first.
  • Review the last three commits on main before I tag the release.
  • What's merged since 2.4? Draft the release notes.

How it works

  1. Register the repositoryIn Code's GitHub tab, add your project's folder. Issues and pull requests need the GitHub CLI, signed in; commits, tests and reviews only need Git.
  2. Turn reports into issuesNew Issue writes a full issue from your short description, with context and acceptance criteria. Or ask Nova to write it from what your users reported.
  3. Auto Tackle itAn AI works on the issue: it creates a branch, implements the fix, runs the tests and opens a pull request.
  4. Review, then mergeOn a commit, Auto Review gives an AI verdict with findings, and Health Check runs every test suite, with no AI. Approve the tackle, then Merge it, or Dismiss it.
  5. Keep the release notesAsk Nova what went in since the last version. She reads the history and writes the notes as a page you can edit.
{{icon:shield-check}}

Your main branch stays yours. Every tackle works on its own branch. Nothing is merged until you choose Merge, and a tackle you dismiss never touches the project.

What you need

GitGit for Windows, or your distribution's git package.
The GitHub CLIgh, signed in with gh auth login, for issues, pull requests and tackles.
A coding providerFor example Codex or Anthropic, connected during setup.
