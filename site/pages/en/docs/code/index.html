Everyday use

Coding sessions.

Code is where agents work on your projects. A session is a persistent AI worker on one project, which you can watch, steer and come back to. Around it, Code shows your commits, issues, tests and branches, and lets you edit files yourself.

What you need

  • Git, for everything in Code. Git for Windows, or your distribution's git package.
  • The GitHub CLI (gh), signed in with gh auth login, for the GitHub features: listing and creating issues and pull requests, and tackles. Commits, branches, tests, reviews and health checks only need Git.
  • Your project's own toolchain, to run its tests.

Code's settings show a Dependencies list with what it found. Choose Check again after installing something.

Add a project

Open the GitHub tab in Code and choose + (Add repository) at the top of the Repos list.

  • Existing checkout: a folder that is already a Git repository. Give it a name and its path, then choose Register. The remote is detected from Git.
  • New project: Code creates the folder, initialises Git on main, and registers it. Choose Create.

Code doesn't clone. To work on a project that only exists on GitHub, run git clone first, then register the folder.

Start a session

  1. New sessionIn Sessions, choose New or press Ctrl+N.
  2. Find the projectFilter to find it. If the project allows branches, a Branch row lets you pick or create one: see Branches and parallel work.
  3. Pick the provider and qualityFast, Standard, Deep or Research. Standard suits most work; Deep and Research take longer and think harder. Then choose Go. Clicking a project's name also starts the session at once, with the settings shown, so set the branch, provider and quality first.
  4. Write the briefThe session starts empty: your first message is the brief. Say what you want, what “done” looks like, and how to check it.

From a repository's header in the GitHub tab, New Session starts one straight away with the defaults.

Working with a session

A session works like a discussion: step squares for every action, approval cards, queued follow-ups, Esc to interrupt. A few things are specific to Code:

  • Plan mode. Press Shift+Tab and the session reads and plans without changing anything. When the plan is ready, choose Execute Plan, or reply to revise it.
  • Status. Each session's dot shows its state: gold while working, teal when idle, grey when stopped, red on error, amber when it's waiting for you. The browser tab gets a (!) while any session waits on you. Alt+↑ and Alt+↓ switch sessions.
  • Info. Alt+I shows the provider, model, quality, cost and tokens, and its Permissions: the one setting you can change while it runs.
  • Coming back. Send a message to a stopped session and it resumes. If you hit your provider's usage limit, the session pauses; send a message after the limit resets.
  • Stop, Dismiss, Close. Stop ends the process and keeps the session listed. Dismiss hides it without stopping. Close does both. Find closed sessions under More › Browse archives and Reopen them.

Reviewing what changed

The Code tab is a file browser and editor. Files an AI session changed recently carry a sparkle, and the Git panel lists Recent AI Changes, uncommitted changes and recent commits. Open a changed file and choose Diff against HEAD to see exactly what moved. Save your own edits with Ctrl+S.

Code doesn't commit, push or merge for you from these panels. Ask the session to commit, or use Git yourself.

Tackles work in your project folder. A tackle switches branches in the main checkout. Don't start one while you or another session are working there.

Letting Nova delegate

You don't have to start sessions yourself. Ask Nova for the work in a discussion, and she can hand it to a Code session on the right project, on its own branch if the project allows it. The discussion shows a Delegated to Code card with Open in Code, and a pink circle while it runs. When the session finishes, Nova gets the result, reviews it, and tells you what happened. She can send the same session more feedback until it's right.

You can open the delegated session in Code at any time to watch it, approve a step, or add a message.

A delegated session doesn't share Nova's memory or the discussion. Nova writes what the session needs into its brief, and that's one more reason to keep your project's decisions in her workspace.
