Going further

Backups.

RedLeaf's database holds your discussions, your agents, their memory and every entity. Back it up on a schedule, and if you want to survive losing the computer, keep an encrypted copy off-site.

What's covered

BackupIncludes
Database backupDiscussions, agents, memory and workspace pages, skills, automations and every other entity. With the Everything scope, the whole database.
Off-site copyThe database, plus RedLeaf's encryption keys, your assets (images, audio, video) and the workspace files.

Neither covers your own project folders, documents or anything else on your disk. Back those up as you normally would, and push code to a remote often.

Database backups

Open Settings › Storage › Database and find Backup.

  • Automatic: Off, Daily or Weekly, and when it Runs at. Automatic backups are off until you turn them on.
  • Scope: Entities only, or Everything.
  • Retention: how many automatic backups to keep, from 1 to 10. Manual backups are kept separately, up to the same number again.
  • The folder: leave it empty for the default, %LOCALAPPDATA%\RedLeaf\backups on Windows.

Back up everything makes one now. Export entities saves your entities on their own. Last backup tells you when the last one ran.

Backups are standard PostgreSQL dumps. There's no restore button for them yet in the preview. If you need to restore one, ask for help on the Leaf Discord.

Off-site copy

The off-site copy goes to a Cloudflare R2 bucket you own. It's encrypted on your computer before it leaves, so Cloudflare only ever stores ciphertext. It's on Windows for now, and only an administrator can set it up.

  1. Create a bucketIn Cloudflare, create an R2 bucket and an access key for it.
  2. Connect itIn Settings › Storage › Backups, choose Set up off-site copy. Enter the Account ID, the bucket, the Data location (choose European Union to keep it in the EU), the Access key ID and the Secret access key.
  3. Save the recovery passphraseRedLeaf shows an eight-word recovery passphrase once. Copying it is blocked on purpose: write it into your password manager by hand, tick I saved it in my password manager, and type it back to confirm. Without it, the copy can't be decrypted.
  4. Turn on nightly copiesBack up every night runs after the local database backup. Back up now runs one straight away.

How long copies are kept

A weekly clean-up drops restore points older than 35 days and keeps one a week for 12 weeks. The bucket is locked: nothing in it can be deleted or overwritten for 30 days, even from RedLeaf, so a mistake or a compromised agent can't erase your history.

Test it before you need it

RedLeaf runs a restore test automatically on the first Sunday of each month. Run one yourself with Run a restore test now. To get something back, choose Restore to a folder: pick what to restore, the restore point and optionally one path. It always lands in a new folder, never over your live data.

For a full recovery on a new computer, RedLeaf writes a how-to-restore file into the bucket. The order is: keys first, then install RedLeaf, then the database, then assets and workspace files.
