Going further

Access levels.

An access level decides what an agent may do in a session without asking you first. There are four, from reading only to running anything. Only you can change them, from Settings, in person.

The four levels

LevelWhat the agent may do
PlanReads and plans. It changes nothing until you let it go ahead.
AskEdits files in the project and asks you before anything else, like running a command.
AutoA safety check approves routine actions and blocks risky ones.
FullDoes anything without asking. Only available while Full access is on.

The default is Auto, with Full access off. Heartbeats, schedules and other unattended sessions can't wait for someone to approve a step, and Auto lets them keep working while still stopping anything risky.

Plan and Auto need a provider that supports them. Where it doesn't, the session uses Ask instead.

Where to set it

ScopeWhere
Every agentSettings › Agent permissions › New sessions. Used by every agent without a level of its own.
One agentThe agent's page, in its Access level field. Choose a level, or Use default.
One sessionThe session's Info dialog, under Permissions. It applies right away.

A session can't go above the level it started with, and an agent can never raise its own level. In Code, Shift+Tab toggles Plan mode and returns to the previous level when you leave it.

Approvals

When an action needs your permission, the agent stops and shows an approval card. Its step square gets an amber ring, and the discussion is marked as waiting for you.

  • Allow once lets this one action run.
  • Allow for this session stops asking about this kind of action until the session ends.
  • Deny refuses it, and the agent carries on without it.

Actions refused by policy, without asking, appear as a short note under the agent's latest reply.

Full access

Turning on Full access in Settings › Agent permissions opens a warning you have to read and accept. It says, in short: with Full access, an agent runs any command without asking. It can delete files, rewrite git history, wipe a database or send your data somewhere else. Usually that would be a mistake. Sometimes it's because something it read, such as a Discord message, an email or a web page, told it to.

Before you turn it on:

  • keep a backup the agent can't reach, and test a restore once;
  • push your code often;
  • know what RedLeaf backs up: its own database, not your other files;
  • keep passwords and API keys out of plain files;
  • prefer Ask or Auto for anything that reads untrusted content, and use Full for one session at a time, when you need it.

Turning it off moves every Full default back to Auto, and live Full sessions to their default level. If the warning's text changes, Full access turns off until you accept the new version.

{{icon:warning}}

Agents read things you didn't write. Web pages, emails and messages can contain instructions aimed at an AI. The lower the access level, the less harm such an instruction can do. That's the real reason to keep Full access for the moments you need it.
